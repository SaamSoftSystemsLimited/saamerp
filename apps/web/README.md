# SaamERP web application demo

Interactive React/TypeScript frontend for customers, contacts, quotations and
module configuration. Synthetic seed data is generated by the Java API against
PostgreSQL on GitHub runners, then published as a static Pages asset. Browser
edits stay in localStorage and can be reset to the seed; no live API is exposed
through GitHub Pages. Do not enter real customer or employee data.

See [CRM workflows, architecture and reproduction](../../docs/CRM_DEMO.md).

## Development

Requires Node 24. The checked-in synthetic fixture supports local development.

```sh
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run dev
```

For a read-only home directory, add `--cache /tmp/saamerp-npm-cache` to install
commands. To use an installed Chromium for browser tests set
`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/path/to/chromium`.

The Pages workflow starts PostgreSQL, verifies the Java backend, seeds/exports
fresh synthetic data, checks persistence across restart, then builds and tests the
frontend before uploading `dist` and deploying it. No passwords or database dumps
are bundled. Relative asset URLs support repository Pages paths and custom domains.
Frontend CI tests the checked-in API-generated fixture separately.

A public Pages demo is not a protected ERP deployment. Browser branch filtering is
presentation only. A separately hosted API with production identity, tenant/branch
membership, permissions and operations is still required for shared live records.
